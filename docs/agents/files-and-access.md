# File access, worktrees and web auth

## Worktrees and project grouping
- `lib/worktree.ts` resolves linked worktree top-levels to the main repo `projectRoot`; `listAllSessions()` attaches it to each `SessionInfo`, so a repo's worktrees group together in the sidebar. A session whose cwd is a removed worktree is inferred back into the main project, never a phantom project row. `/api/models` resolves a cwd that is gone the same way (a finished sub-agent run removes its worktree, and its session still names it). `/api/project-trust` does not fall back: trust is per path, the repo's decision is not the removed folder's, and trusting a folder that is gone is refused, so a GET answering for the repo would only offer a Trust button that fails.
- The root is the folder holding the common git dir only when that dir is its `.git`, or a bare repo a `.git` file there points at (`project/.bare`). Any other bare clone (`parent/repo.git`) is its own root (#1049): its parent may hold other clones, whose worktrees would all fall into one project, incorrectly grouping unrelated repositories.
- `/api/worktrees` validates the selected existing project directory before operating. New worktrees go under `<mainCheckout>/.worktrees/<sanitized-branch>`, including when called from a linked checkout or its subdirectory. Creation requires the project to ignore `.worktrees/` and refuses a symlink there; it never edits the target project’s ignore policy. An existing branch is reused, else `git worktree add -b` creates it. Removed internal paths and historical sibling `-worktrees` paths retain read-only project grouping; execution cwd is never relocated. Removing a dirty worktree answers `409 { dirty: true }`, and the UI asks before retrying with `force`.
- Two places switch or create worktrees, one component (`components/ProjectWorktreePicker.tsx`) on the sidebar's one listing of its cwd (`GET /api/worktrees?cwd=`, refetched when the cwd moves). The files' worktree box (the section below the sessions or the Files tab, whichever the layout shows; in the head above the explorer, beside the project box below the sessions, under it in the tab) switches, creates and removes; it shows at the top of a git checkout, a disabled box says why in a subdirectory of one (its root has the worktrees), and a folder outside any repository has no worktree box at all, the project box taking the whole width (the listing's `isGit` tells the two apart). A folder the listing last found outside git shows no "checking" box while it is listed again, which would only go and widen the project box: the browser keeps the last 50 such folders (`loadNonGitCwds()` / `rememberCwdGitStatus()` in `lib/sidebar-prefs.ts`, read-modify-write so other tabs' stay; one found in git leaves), so a reload knows them before its listing answers, the default dated folder included; only a folder this browser never listed shows the box once. The bar above a fresh composer (`components/NewSessionContextBar.tsx`) shows the same list under the same rule, and removes nothing. Both create through the sidebar (`createWorktree()`, also `SessionSidebarControl.createWorktree()`: `POST` with the project root); the files' picker then moves the sidebar's cwd there, the bar starts the new session there; opening either menu refetches the listing. Removal is `DELETE` with the project root; a dirty checkout answers 409 `dirty` and the picker asks before `force`. A group's "+" asks nothing: it starts in the current worktree or another project's root. Clicking a session still moves the cwd to its worktree implicitly.
- git prints POSIX-style absolute paths even on Windows: every path read from git goes through `toNativePath()` (`lib/paths.ts`) before it is compared or returned, and paths are compared with `samePath()`, never `===` (otherwise `isTopLevel` is always false on Windows and the worktree switcher hides). Branch names are not paths and keep their forward slashes. Browser code cannot apply Node path rules, so `/api/worktrees` resolves `currentWorktreePath` server-side and the sidebar uses it for highlighting and the removal fallback.

## File access
- Reader's file interface follows the operating-system permissions of the Reader process. It does not maintain a separate read/write directory list. Legacy `file-permissions.json` files and their initialization markers are left untouched for rollback; the retired settings endpoint returns 410.
- `/` is a valid workspace. `encodeFilePathForApi()` uses an encoded slash for the root and preserves UNC paths, which `filePathFromApiSegments()` decodes. Endpoints continue to reject `..` path segments.
- Directory links can be browsed without approval; file links are read and edited at their target. Broken links remain visible. Rename and trash operate on the link itself, not its target. Trash still requires confirmation in the UI and uses the system trash. When a linked worktree is trashed, Reader unregisters that specific worktree from Git after the move; a failed unregister is reported as a partial success.
- File and configuration saves keep their existing version checks, size limits, file-name validation and atomic-write protections. Project configurations may point outside the project; a shared target edited through different paths can still receive a later overwrite.
- File-tree visibility follows the user's explorer filters, including hidden files and Git-ignored entries; the eye control can reveal `.git`. Visibility is not access control. Project trust, MCP choices, read-only session rules, authentication, and request Host/Origin checks remain separate.
## When the file tree reloads
- No watcher and no polling: the tree (root, every open folder, git status) reloads when a run ends, at most once a second while a run's tools finish (any top-level tool but the read-only preset's `read`/`grep`/`find`/`ls`: AppShell's `handleToolEnd`, from `useAgentSession`'s `onToolEnd`), when the window gets focus (changes made in an editor or terminal), after an upload, and on the refresh button (#1144). A reload keeps the open folders and shows no spinner. A collapsed folder listed before is only marked: it lists again when next opened, or a file dropped onto its row would be missing when it opens.
- Open folders are kept per cwd for the page's life (`lib/file-tree-expansion.ts`: a module-level LRU of 20 folders, the one left longest ago dropped first; gone on reload). A cwd change saves the outgoing folder's set and restores the incoming one's (none for a folder not kept), so picking a session in another project and coming back does not fold the tree; an explorer that unmounts saves its set too. Highlights and the upload summary, conflict and error still start over. Nothing is listed ahead: the roots unmount while the new cwd loads, so each restored folder mounts open and lists itself (`TreeNode`'s mount effect), level by level as its parents list. A folder gone since is never listed, so its path never matches and stays inert; one that fails to list shows the error in place. The set saved is the one last committed (`expandedPathsRef`, synced by an effect declared before the cwd effect), never the state a cwd-change render still holds.

## Uploads and chat drops
- The explorer's Upload button and a non-image file dropped onto the chat share one client, `uploadFiles()` (`lib/file-upload-client.ts`), and the one endpoint, `POST /api/files/<cwd>?type=upload`; never add a second write path for drops. The explorer asks `upload-check` first and lets the user replace or skip; a chat drop goes straight to `conflict=skip`, so it never replaces a file. It then inserts `@name` for every file the response lists as uploaded *or* skipped (a skipped name is a file already there, often the very file dragged out of the project) and says in a notice that the mention points to the existing file.
- Dropped images still attach to the prompt. Folders are left out with a notice: the endpoint writes flat file names only (`validateUploadFileNames()`), and the browser cannot tell where a dropped file lives on disk, so the copy always lands in the cwd root.
- The composer's attach button (#1101, for phones that cannot drop) is a drop by another route: its file input has no `accept` list (and no `capture`, so phones still offer photos and the camera), and `ChatInput` hands the whole selection to ChatWindow's `onAttachFiles`, which calls the drop handler. Images attach, other files upload and get mentioned, with the same notices; keep one path for both. A `ChatInput` without `onAttachFiles` keeps `accept="image/*"`.
- Files dropped onto the explorer take the Upload button's path (`upload-check`, replace or skip, summary, highlights), aimed at a folder: a folder row takes the drop into that folder (rows stop `dragover` and `drop`, so the deepest one under the pointer wins); anywhere else, file rows included, it lands in the cwd. The hint naming the target is pinned to the bottom of the files box with `pointer-events: none`: above the tree it pushed every row down as a drag came in, moving the target under a still pointer. Folders are left out with the chat's notice.

## Source view languages
- `/api/files ?type=read` names a file's language by its extension (`EXT_TO_LANGUAGE` in the route). `FileViewer` hands it to Prism as is, and a name Prism lacks renders plain with no error, so every value but `text`, `pdf` and `word` must be a language `refractor/all` registers (`app/api/files/language-route.test.mjs`). `html` and `markdown` also turn on Preview and make it the default, so a template that is not a page (`.vue`, `.svelte`, `.astro`) takes `markup`. `.m` stays `text`: Objective-C and MATLAB both use it widely, and either grammar miscolors the other (MATLAB's `%` comments come out as operators); `.mm` is Objective-C++ only. `.conf` stays `text` as well: nginx, Apache and tmux configs are not INI (`.cfg` and `.ini` are). Past 1,000 loaded lines the source view is not highlighted at all (`SOURCE_HIGHLIGHT_MAX_LINES`, #469).

## CSV/TSV files open as a table
- `.csv` / `.tsv` (matched by extension, `isDelimitedTablePath()`) open in `FileViewer`'s Preview mode as `components/DelimitedTable.tsx`, the way markdown and HTML open rendered; Source stays one click away and a restored choice wins. No server change: `/api/files ?type=read` still answers `language: "text"` for them.
- `lib/delimited-table.ts` parses RFC 4180 itself (quoted delimiters, `""`, line breaks inside quotes, LF/CRLF, BOM, blank lines skipped) and is lenient where files are not (stray quotes, ragged rows). A `.tsv` always splits on tabs; a `.csv` takes `,` unless its first records split more consistently on `;`, tab or `|` (Excel in many locales writes `;`). The first record is the header.
- The gutter is the file line each record **starts** on (counted by LF, as the source view numbers lines), not the record index, so a quoted field with line breaks does not shift later rows.
- Large files arrive in 256 KB chunks with "Load more". The table shows a loaded prefix too (`complete: false`): its last record is dropped unless a line break outside quotes ends it, so a record cut mid-field never shows; it appears once the next chunk loads. Markdown and HTML keep their preview off while truncated.
- Rows have one fixed height and only those around the viewport are rendered (`visibleRowRange()`, the SessionTree approach; no virtualization library). The table scrolls inside the viewer's own content box (`scrollRef`), so its scroll position is saved and restored like the source view's; it reads the box in a passive effect because the parent's ref is not attached yet in the child's layout effects. Column widths come from up to 500 sampled rows, clamped to 64–420 px; a cell ellipsizes and its full value is its tooltip. Gutter and header use `--bg-panel`, opaque, so columns scrolling under the sticky strips never show through.

## Web password throttling
- `lib/auth-throttle.ts` is deliberately global, not per-IP (its header says why). Failures double the delay (1 s → 60 s cap) for everyone; a success or 5 idle minutes resets it. The reset window must stay longer than the max delay, or waiting out one block restarts the burst.
- State lives on `globalThis` under `Symbol.for("pi-web:auth-throttle")`, so it survives hot reload and `proxy.ts` and the route handlers share it under both `next dev` and `next start`. Tests reset it with `recordAuthSuccess()`.
- `POST /api/web-auth` and every `Authorization: Basic` header on `/api/*` share the counter; `proxy.ts` checks Basic before its `/api/web-auth` exemption, so `GET /api/web-auth` is no unthrottled password oracle. A valid session cookie is checked first and never blocked. While blocked, Basic gets `429` even with the right password, and a Basic success never resets the counter (`proxy.ts` explains both).
